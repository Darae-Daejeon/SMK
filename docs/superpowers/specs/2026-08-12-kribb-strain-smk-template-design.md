# KRIBB 균주 SMK 공통 템플릿 설계 명세

## 1. 목적

- 한국생명공학연구원 행사에서 활용할 균주 기술판매용 SMK 템플릿 구축
- 공통 HTML 템플릿 1개와 공통 JSON 데이터 1개로 여러 기술 소개
- 화면에서는 반응형 긴 문서로 제공
- 인쇄에서는 A4 세로 2~3페이지로 제공
- 특허·실험 원문을 연구학습용이 아닌 기술판매용 정보로 재구성

## 2. 이용 흐름

1. 랜딩페이지가 공통 JSON에서 기술 목록 로드
2. 사용자가 기술 카드의 `보러가기` 선택
3. `smk.html?tech={기술ID}` 주소로 이동
4. 공통 상세 템플릿이 URL의 기술 ID 확인
5. 공통 JSON에서 해당 기술 검색
6. 균주·특허·실험·차트·적용제품·IP 포트폴리오 렌더링
7. 필요 시 브라우저 인쇄 기능으로 A4 PDF 저장

## 3. 정보 구조

### 3.1 문서 상단

- 첫 페이지 또는 화면 상단에 KRIBB 공식 국·영문 시그니처 표시
- 기술명, 연구자명, 균주 프로필 문구 표시
- 기술분류 및 유형을 제목 하단의 압축형 4칸 영역으로 표시
  - 대분류
  - 중분류
  - 소분류
  - 확장유형
- 분류값은 JSON 입력값만 표시
- 분류 영역은 본문 목차에 포함하지 않음

### 3.2 고정 목차

1. 균주 정보
2. 특허 정보
3. 실험 내용
4. 관련 데이터
5. 기술(균주) 적용제품
6. 기술 핵심요소
7. 기술활용 절차
8. 연구자 보유 균주 및 특허

### 3.3 섹션별 표시 규칙

#### 01 균주 정보

- 표 머리글 고정
  - 수탁번호(기탁일자)
  - 미생물명
  - 미생물종류
  - 균주 별칭
  - 유래
  - 핵심 특성
- 미생물 학명은 이탤릭체 적용 가능
- 긴 값은 줄바꿈하되 행 전체 높이 자동 확장

#### 02 특허 정보

- 표 머리글 고정
  - 특허명칭
  - 등록번호
  - 핵심 차별성
- 출원 단계 기술은 등록번호 필드에 출원번호 또는 상태를 입력할 수 있음
- 템플릿은 입력된 표기를 임의로 변경하지 않음

#### 03 실험 내용

- 특허·논문 원문을 기술판매용으로 요약
- 실험별 권장 구성
  - 실험 목적
  - 시험 대상 또는 모델
  - 처리 조건
  - 평가 방법
  - 주요 결과
  - 사업적 의미
- 의미 단위 실험 블록으로 표시
- 원문 실험 절차의 과도한 나열 방지

#### 04 관련 데이터

- 기술별 1~3개 차트 표시
- 4개 이상은 허용하지 않음
- 넓은 화면은 차트 수에 따라 1~3열 배치
- 모바일은 1열 배치
- SVG 기반 차트 사용
- 각 차트에 다음 정보 표시
  - 제목
  - 단위
  - 범례
  - 데이터 라벨
  - 원문 도면 번호 또는 출처
  - 원문 수치·추정 수치 구분
- 정확한 수치가 없는 경우 숫자를 임의 생성하지 않음
- 수치 재현이 불가능한 경우 원문 도면 또는 정성적 경향 요약 사용

#### 05 기술(균주) 적용제품

- 3~5개 제품 또는 서비스 표시
- 표 머리글 고정
  - 우선순위
  - 적용 가능제품·서비스
  - 활용방향
- 화면에서는 카드형 또는 표형으로 표현 가능
- 인쇄에서는 정보 누락 없이 표 형태 유지

#### 06 기술 핵심요소

- 원문 근거의 핵심요소 3~4개 권장
- 균주 고유성, 효능, 안전성, 확장성, 권리성 중 실제 근거가 있는 항목만 사용
- 핵심요소별 제목과 짧은 설명 표시

#### 07 기술활용 절차

- 4단계 고정
  1. 상담 신청
  2. 물질이전·기술실시계약
  3. 균주 스탁 제공
  4. 사업화
- 단계 번호, 진행선, 방향 표시, 세부 설명 적용
- 화면에서는 가로 흐름형 사용
- 모바일에서는 세로 흐름형 사용
- 인쇄에서는 4단계 전체를 한 섹션으로 유지

#### 08 연구자 보유 균주 및 특허

- 섹션명 유지
- 연구자의 연관 균주·특허를 보여주는 IP 포트폴리오 영역
- 최대 5행
- 현재 소개 기술과 연관성이 있는 확인된 항목만 표시
- 권장 열
  - 수탁번호
  - 균주명
  - 특허명
  - 상태
  - 핵심 용도

## 4. 화면 디자인

### 4.1 기본 방향

- `C 균주 카탈로그형`을 기본 디자인으로 사용
- `A 정밀 보고서형`의 표·근거·차트 표현 결합
- 향후 사용자가 `A로 변경`을 요청하면 정밀 보고서형으로 전환 가능하도록 디자인 토큰과 레이아웃 분리

### 4.2 색상

- KRIBB 공식 CI의 Light Blue와 Deep Blue 계열 사용
- 진한 파랑
  - 주요 제목
  - 섹션 번호
  - 표 상단선
  - 핵심 데이터 강조
- 하늘색
  - 진행 상태
  - 차트 주요 계열
  - 소제목과 보조선
- 청회색
  - 표 머리글
  - 기술분류 영역
  - 카드 배경
- 검정·진회색
  - 본문
  - 수치와 단위
- 비교군 구분이 필요할 때만 제한적 보조색 사용

### 4.3 로고

- 첫 화면과 인쇄 첫 페이지에 공식 국·영문 시그니처 사용
- 인쇄 2페이지 이후에는 공식 컬러 심벌 사용
- 흑백 인쇄용 공식 흑백 심벌 자산 보유
- 로고 비율, 색상, 내부 간격 임의 변경 금지

### 4.4 과학 모티프

- 세포·콜로니·미생물 형태의 옅은 SVG 워터마크 사용
- 농도는 약 5~8% 수준
- 제목 주변 또는 페이지 하단 잔여 공간에 제한 적용
- 본문, 표, 차트 뒤에는 배치하지 않음
- 흑백 인쇄에서도 본문을 방해하지 않도록 명암 제한

## 5. 반응형 사이드바

### 5.1 넓은 화면

- 기본 상태는 약 76px 너비의 얇은 진행 레일
- 01~08 섹션 위치를 점과 진행선으로 표시
- 현재 섹션은 큰 점, 번호, 강조색으로 표시
- 지나온 섹션은 하늘색 점과 진행선으로 표시
- 마우스 오버 또는 클릭 시 약 220px 목차로 확장
- 펼쳐진 사이드바는 본문을 밀지 않고 오버레이로 표시
- 목차 항목 선택 시 해당 섹션으로 부드럽게 이동

### 5.2 스크롤 연동

- 각 섹션의 화면 진입 상태 감지
- 현재 화면에서 대표성이 가장 높은 섹션을 활성 항목으로 판단
- 활성 번호, 목차 행, 진행선 길이 자동 갱신
- URL 해시에 `#section-01`~`#section-08` 반영
- 직접 링크 접속 시 해당 섹션으로 이동

### 5.3 태블릿·모바일

- 고정 레일 대신 화면 왼쪽 가장자리의 작은 목차 탭 표시
- 탭에 현재 섹션 번호 표시
- 탭 선택 시 목차 서랍 표시
- 서랍 외부 선택 또는 항목 이동 후 닫힘
- 키보드와 터치 조작 지원

### 5.4 인쇄

- 사이드바, 모바일 탭, 화면용 탐색 요소 전체 숨김

## 6. 화면 레이아웃

- 화면 본문은 A4 비율로 제한하지 않음
- 하나의 긴 반응형 문서로 표시
- 데스크톱에서 본문 최대 폭과 좌우 여백만 관리
- 노트북, 태블릿, 모바일에 따라 표·차트·프로세스 재배치
- 화면용 섹션 간격은 읽기 흐름 중심으로 설계

## 7. 인쇄 레이아웃

### 7.1 기본 규격

- 인쇄 시에만 A4 세로 적용
- 목표 분량 2페이지, 최대 3페이지
- 글자를 과도하게 축소하여 2페이지에 강제 배치하지 않음

### 7.2 절대 분할 금지 규칙

- 목차 섹션 1개를 최소 인쇄 단위로 사용
- 섹션 전체가 현재 페이지 잔여 공간에 들어가지 않으면 다음 페이지로 전체 이동
- 섹션 제목, 문단, 표, 차트, 프로세스를 다른 페이지로 분리하지 않음
- 다음과 같은 단어·문장 중간 분할 금지
  - 1페이지 끝: `기존 박테`
  - 2페이지 시작: `리아 항암 접근과 달리`

### 7.3 페이지 구성 로직

1. JSON 렌더링 완료
2. 인쇄용 서체와 폭 적용
3. 각 섹션의 실제 높이 측정
4. A4 인쇄 가능 높이와 비교
5. 현재 페이지에 들어가면 섹션 전체 배치
6. 들어가지 않으면 다음 페이지 첫 부분으로 전체 이동
7. 남은 하단 공간에만 과학 모티프 배치
8. 전체 결과가 2~3페이지인지 검증

### 7.4 인쇄 머리말·꼬리말

- 첫 페이지에 공식 국·영문 시그니처
- 2페이지 이후 공식 컬러 심벌
- 페이지 번호 표시
- 브라우저 기본 머리말·꼬리말은 사용하지 않음

- 랜딩페이지와 상세페이지가 동일한 JSON 사용
- 상세 URL 형식: `smk.html?tech={기술ID}`

## 9. JSON 데이터 원칙

- 모든 기술을 `technologies` 배열에 저장
- 기술별 고유 ID 필수
- 화면 표시용 텍스트와 차트 원자료 분리
- 차트 데이터에 단위, 출처, 도면 번호, 수치 상태 포함
- 배열 길이 제한
  - 관련 데이터: 1~3개
  - 적용제품: 3~5개
  - 핵심요소: 권장 3~4개
  - 활용절차: 4개 고정
  - 연구자 보유 균주 및 특허: 최대 5개
- JSON 입력 안내서에 각 필드의 한글 설명과 예시 제공

## 10. 오류 처리

- 기술 ID가 없으면 기술 목록으로 이동 가능한 안내 표시
- JSON 로드 실패 시 파일 경로와 재시도 안내 표시
- 필수 필드 누락 시 화면 상단에 검토 경고 표시
- 차트 값과 라벨 수가 다르면 해당 차트를 출력하지 않고 오류 위치 표시
- 제한 개수를 초과하면 조용히 자르지 않고 검토 경고 표시
- 인쇄 결과가 3페이지를 초과하면 인쇄 전 경고 표시
- 섹션이 A4 한 페이지 높이를 초과하면 해당 섹션명을 포함한 경고 표시

## 11. 원문과 공개 범위

- 박승환 등록특허 원문을 첫 번째 예시 데이터의 근거로 사용
- P2025-033 미공개 출원서는 두 번째 재사용성 검토 자료로 사용
- 미공개 출원서 기반 데이터는 공개 승인 전 GitHub Pages에 배포하지 않음
- 특허 원문에서 확인되지 않는 수치·효능·권리범위 임의 생성 금지
- 공개 전 특허 서지정보와 차트 수치를 원문에 대조

## 12. 검증 기준

### 12.1 기능 검증

- 랜딩페이지가 JSON의 기술 목록을 정확히 표시
- `보러가기` 링크가 동일한 상세 템플릿으로 연결
- 기술 ID에 따라 다른 데이터 표시
- 사이드바가 01~08 섹션과 정확히 연동
- URL 해시 직접 접속과 목차 이동 작동

### 12.2 반응형 검증

- 데스크톱, 노트북, 태블릿, 모바일 폭에서 가로 넘침 없음
- 표, 차트, 활용절차의 모바일 재배치 확인
- 사이드바와 모바일 목차 서랍의 키보드·터치 동작 확인

### 12.3 인쇄 검증

- Chrome·Edge 계열 브라우저에서 A4 세로 PDF 생성
- 2~3페이지 여부 확인
- 01~08 각 섹션의 시작·종료 페이지 확인
- 단어, 문장, 문단, 표, 차트, 활용절차 분할 없음
- PDF 각 페이지를 이미지로 렌더링하여 잘림·겹침·가독성 육안 확인
- 배경 그래픽 인쇄 설정에 의존하지 않고 로고와 워터마크 출력

## 13. 1차 구현 완료 조건

- 공통 랜딩페이지와 상세 템플릿 동작
- 박승환 기술 예시 데이터 렌더링
- P2025-033 기술의 비공개 로컬 예시 렌더링
